## boot.img 结构（vivo 非标准 AOSP 头）

| 偏移 | 字段 | 值 |
|---|---|---|
| 0x00 | magic | `ANDROID!` |
| 0x08 | kernel_size | 52,062,676 |
| 0x0C | ramdisk_size | 原厂 1,479,636 / 补丁 1,967,649 |
| 0x14 | header_size | 1584 |
| 0x24 | page_size | **读出为 0，但实际是 4096**（vivo 坑） |
| 0x28 | header_version | 4 |
| 0x1000 | kernel 起始 | ARM64 Image，magic 在 +0x38 |
| 0x31A8000 | ramdisk 起始 | **lz4 legacy 帧**（magic `02214c18`） |

> `lz4.frame` 解不了 legacy 帧，必须手写 4 字节块循环 + `lz4.block.decompress(uncompressed_size=1<<23)`。
> ramdisk 内是 cpio newc，字段偏移：`filesize@54`、`namesize@94`、`name@110`。

## KernelSU 补丁到底改了什么

**内核本体一个字节都不改**，只改 ramdisk：

| 原厂 ramdisk | 补丁后 ramdisk |
|---|---|
| `init`（2,739,792 B） | 改名为 `init.real` |
| — | 新增 `init`（603,008 B，KSU 加载器） |
| — | 新增 `kernelsu.ko`（官方 v3.3.1 为 379,016 B） |
| — | 新增 `ksu_config`（9 B，内容 `bundled=1`） |

## 反直觉结论（重要，别误判）

bundled `kernelsu.ko` 的 vermagic 是 `5.10.252-dirty SMP preempt mod_unload modversions aarch64`，
而内核是 `5.10.246-gki-g02b2e21da816`。

**看起来不匹配，实际能加载成功** —— `/proc/modules` 显示：
`kernelsu 212992 2 - Live (O)`

vivo 内核允许跨 minor 版本加载 LKM。**判定标准只有一个：`/proc/modules` 里有没有它。**

## 固件包

- 结构：AOSP block OTA
- 关键文件：`boot.img`（zip 根目录）、`META-INF/com/android/metadata`、`firmware-update/*`
- metadata 里看 `post-version`、`post-build`、`anti-rollback-level`
- `anti-rollback-level = 0` 才允许降级

## 环境（Windows）

- Git Bash 里操作必须先 `export MSYS_NO_PATHCONV=1`，否则 `adb pull` 的远程路径被改写
- 直连 `github.com` 会 `Connection was reset`，需走系统代理（如 `127.0.0.1:7897`）
- KernelSU 管理器：官方 `me.weishu.kernelsu` v3.3.1 / Next `com.rifsxd.ksunext` v3.4.2
